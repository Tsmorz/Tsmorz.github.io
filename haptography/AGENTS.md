# Haptography (`/haptography/`)

**This repo is the sole source of the website.** Firmware and Python processing live in nrf-controller;
there is no website publish/copy task there. `/haptography/bench/` is only a redirect to the studio.
`storage.js` imports the old bench database once, atomically, without deleting its originals.
The static fixtures in `tests/fixtures/capture/v6/` are generated by nrf-controller's `task capture-contract`;
`v5/` stays so older recordings keep reading.
When the capture protocol changes, bring over the new versioned fixture folder and update the reader and
contract tests together. Site CI must work without that private repo or a C compiler.

Three workspaces: **Record** (record, then replay a take in place: listen, "Play on actuator",
"Recreate selection"), **Library** (common waveforms to play and star) and **Recreate** (a selected
stroke becomes a drive; measure, refine, save). Keep it that simple: new tools go inside one of
these, collapsed by default, not into a fourth tab. `index.html` has front matter only to render
`_data/haptography.yml`; it uses its own `studio.css`, no site layout. `app.js` owns the serial
connection, raw takes, recovery spool, live scope and collection quality; `body[data-mode]`
(live/replay/spectrum) decides which Record panels show. `studio.js` owns the board for playback
(`playOnce`, `playSelection`), the waveform editor, response profiles, experiments and A/B.
`library.js` draws the Library; `library-core.js` (no DOM) renders `_data/haptography.yml`'s
`library` entries (kinds documented above that list) and pads short drives to 100 ms, because
`windowRms` measures a shorter clip over its own length and would hold a click to the buzz budget.
Favorites live in the IndexedDB `studio` store under `library`; saved Recreate versions appear in
the Library as `v:<id>`. `speakers.js` is the header's Speakers switch: every actuator playback
is also heard on the computer when it is on, and in Demo the speakers are the only output (the
Library and "Play on actuator" never "play" on the simulated actuator). The firmware takes these
as uploaded clips (CLIP_BEGIN/DATA/PLAY); it does not store a library of its own yet.
Its design is a compact desktop signal editor: neutral surfaces, a single toolbar, blue signal
traces, and flat parameter controls. No display headings, slogans, decorative cards or tinted
page backgrounds. Desktop panels scroll independently within the window; narrow screens put
the signal plots before the parameter controls. Keep canvas sizes in CSS.
`haptics-core.js` is hardware-free signal processing (1600 Hz analysis grid; g for acceleration,
fractions of full scale for drive), mirroring the model format and inverse/correction approach in
`../nrf-controller/recording/haptics/`. `device.js` sends CRC/COBS commands on the recorder's port,
matches ACKs by type and sequence number, uploads chunks at sample offsets, and aligns measured IMU
samples to the device's PLAYBACK timestamp. Playback capacity and rates come from INFO, not the UI.
The firmware's TacHammer-ready flag only says I²S started; it cannot detect a connected actuator.

Raw recordings are never trimmed or overwritten by editing. Excluded spans are `bad` labels and
do not contribute strokes to dataset coverage. Simulated takes/profiles/measurements are labelled;
simulated actuator profiles never compensate physical playback. IndexedDB v2 adds a `studio` store
without replacing the existing takes/raw/spool stores. Experiments preserve the raw selected target,
settings, profile, drive, measurement, trial raw bytes and assessments. JSON exports round-trip;
folder exports also contain 16 kHz `drive.wav` and trial `raw.bin` files. There is no ERM since protocol 6
(2026-11-16): no output choice, ERM plot or ERM gain; older experiments and profiles import with their
ERM parts ignored.

`task check:haptography` (in `check:fast` and `task ci`) tests the DSP against known signals, response
identification and correction, protocol retries and offsets, measurement coverage and exports. The Node
tests also decode C-generated wire/health/profile fixtures and compare session exports to the Python fixture.
Physical preview retains the tested 70% ceiling (95% headroom) and 7000-count/100 ms RMS budget;
imports are validated before upload, and failures and cancellation send STOP.
`tests/haptography/library.test.mjs` renders every catalog entry (reads the YAML through Ruby) and
checks the drive limits. After `task build`, `task shot -- /haptography/ --eval-file tests/haptography/browser.js --full`
exercises collection, replay, exclusion/undo, target selection, simulated identification, matching,
correction, variants, A/B cancellation, the Library (favorites, filters, export) and IndexedDB storage. Repeat with `--phone` for the narrow layout.
These checks use simulated actuators; real TacHammer response and timing still require a board.

`tests/haptography/migration-browser.js` checks bench recordings, unsaved spools and idempotent import.

`tests/haptography/serial-browser.js` exercises the real UI against a synthetic Web Serial peer
(protocol 6, TacHammer clip upload, recording, completion timestamps, STOP, a Library tile played on the
board, and authorized-port reuse).
